# 1. Назначение

Документ описывает существующие REST endpoints управления собственным пользовательским аккаунтом.

Источник реализации:

- `user/web/controller/MeController.java`;
- `user/web/mapper/MeWebMapper.java`;
- `user/web/dto`;
- `auth/service/PasswordService.java`.

API использует идентичность аутентифицированного пользователя, а не переданный клиентом произвольный userId.

---

# 2. Реализованные endpoints

| Метод | Endpoint | Назначение | Успех |
|---|---|---|---|
| GET | `/api/me` | Получить собственный профиль | 200 |
| PATCH | `/api/me/profile` | Изменить собственный профиль | 200 |
| PATCH | `/api/me/password` | Изменить пароль | 204 |

Все три операции требуют аутентификации.

Используется JWT Bearer authentication.

---

# 3. Получение профиля

`GET /api/me`

Возвращает сведения об аккаунте и профиле текущего пользователя.

Результат зависит от роли.

В коде предусмотрены:

- `ClientMeResponse`;
- `SpecialistMeResponse`.

Обе структуры реализуют интерфейс `MeResponse`.

## 3.1. Общие данные

Оба варианта содержат:

- `account`;
- `profile`.

`account` формируется через `UserAccountResponse` и включает:

- `id`;
- `email`;
- `role`.

## 3.2. CLIENT

Профиль клиента содержит:

- `id`;
- `firstName`;
- `lastName`.

## 3.3. SPECIALIST

Профиль специалиста содержит:

- `id`;
- `firstName`;
- `lastName`;
- `approvalStatus`.

## 3.4. HTTP

Успех: 200 OK.

Response содержит `Cache-Control: no-store`.

Контроллер документирует:

- 401 — отсутствует или недействительна аутентификация;
- 403 — учётная запись неактивна.

---

# 4. Изменение профиля

`PATCH /api/me/profile`

Endpoint обновляет разрешённые поля собственного профиля.

Текущая реализация допускает:

- `firstName`;
- `lastName`.

Request body должен быть непустым JSON-объектом.

Неизвестные поля запрещены.

Значения переданных полей должны быть строками.

Пример допустимой структуры:

```json
{
  "firstName": "Anna"
}
```

Можно передать одно или оба поддерживаемых поля.

Неуказанное поле не должно автоматически трактоваться как команда очистки.

Обработка запроса выполняется через `MeWebMapper` и `CurrentUserProfileService`.

При успешном обновлении возвращается актуальный `MeResponse`.

Успех: 200 OK.

Ошибки, документированные контроллером:

- 400 — некорректный запрос;
- 401 — требуется аутентификация;
- 403 — учётная запись неактивна.

---

# 5. Изменение пароля

`PATCH /api/me/password`

Request DTO: `ChangePasswordRequest`.

Поля:

- `currentPassword`;
- `newPassword`.

Оба поля обязательны.

В действующей password policy новый пароль должен соответствовать установленным ограничениям.

Описание контроллера указывает длину от 15 до 128 Unicode code points и требование отличия от текущего пароля.

## 5.1. Успешное изменение

После проверки текущего пароля и успешного изменения:

- изменяется password hash;
- отзываются refresh-сессии пользователя;
- текущая refresh cookie очищается.

Ответ: 204 No Content.

Ранее выданные access JWT не обязательно становятся мгновенно недействительными.

## 5.2. Ошибки

Контроллер документирует:

- 400 — некорректный запрос, неверный текущий пароль или нарушение password policy;
- 401 — требуется аутентификация;
- 403 — отказ в доступе или CSRF failure;
- 409 — конкурентное изменение пароля.

---

# 6. Авторизация

Доступ определяется текущим аутентифицированным пользователем.

Frontend не должен самостоятельно выбирать другого владельца профиля.

Отправка произвольного userId не является частью этих endpoints.

При этом наличие действующего JWT не отменяет необходимость проверки актуального состояния пользователя.

---

# 7. Границы текущей реализации

Этот документ описывает только операции `MeController`.

Он не объявляет реализованными:

- полный набор пользовательских настроек;
- изменение роли;
- административное управление аккаунтом;
- редактирование всех полей профессионального профиля;
- загрузку документов и фотографий;
- frontend account management UI.

Дополнительные операции требуют собственных контроллеров и API-контрактов.

**Статус: CURRENT IMPLEMENTATION — операции собственного аккаунта сверены с `MeController` в `psyweb/main`.**
