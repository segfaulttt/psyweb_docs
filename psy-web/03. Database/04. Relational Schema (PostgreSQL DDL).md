## Assumptions

- PostgreSQL
- `BIGSERIAL` как ID 
- Enums храним как `VARCHAR` + CHECK (чтобы не усложнять миграции)
- Booking — центральная транзакционная сущность
- Slot = atomic unit of availability

# SPECIALIST_PROFILE

```sql
CREATE TABLE specialist_profile (    
	id BIGSERIAL PRIMARY KEY,    
	user_id BIGINT NOT NULL UNIQUE REFERENCES "user"(id) ON DELETE CASCADE,
	first_name VARCHAR(100),    
	last_name VARCHAR(100),    
	approval_status VARCHAR(20) NOT NULL DEFAULT 'PENDING'
	    CHECK (approval_status IN ('PENDING', 'APPROVED', 'REJECTED')),
	rating_avg DOUBLE PRECISION DEFAULT 0
);
```

`specialist_profile` represents Specialist core data.

Public biography and configurable page content are not stored as generic fields of the core Specialist record.

Professional education, qualifications, supporting documents, and their verification state require separate structured models when that functionality is introduced.

`approval_status` represents platform approval of the Specialist and must not be reused as verification state for individual qualifications or credentials.

The exact persistence model for future public-profile and qualification subsystems is outside the current MVP core schema.

# AVAILABILITY_SLOT

```sql
CREATE TABLE availability_slot (
    id BIGSERIAL PRIMARY KEY,
    specialist_id BIGINT NOT NULL REFERENCES specialist_profile(id) ON DELETE CASCADE,
    start_time TIMESTAMP NOT NULL,
    end_time TIMESTAMP NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'FREE'
        CHECK (status IN ('FREE', 'RESERVED', 'BOOKED', 'CANCELLED')),
    CHECK (start_time < end_time)
);
```

AvailabilitySlot uses the following lifecycle states:

* `FREE` — active availability without a current hold or Booking occupancy;
* `RESERVED` — temporarily held by an ACTIVE Reservation;
* `BOOKED` — occupied by a confirmed Booking;
* `CANCELLED` — availability removed by the specialist and retained for history.

`CANCELLED` is terminal.

A cancelled slot is not reactivated. Reopening the same time creates a new AvailabilitySlot record.

The database must allow historical Reservation and Booking records to remain associated with the same slot.

# RESERVATION

```sql
CREATE TABLE reservation (
    id BIGSERIAL PRIMARY KEY,
    client_id BIGINT NOT NULL REFERENCES "user"(id),
    slot_id BIGINT NOT NULL REFERENCES availability_slot(id),

    status VARCHAR(20) NOT NULL
        CHECK (status IN ('ACTIVE', 'CONFIRMED', 'CANCELLED', 'EXPIRED')),

    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    expires_at TIMESTAMP NOT NULL,
    cancelled_at TIMESTAMP,
    cancellation_initiator VARCHAR(20),

    CHECK (expires_at > created_at)
);
```

A Reservation represents a temporary client hold on an AvailabilitySlot.

An `ACTIVE` Reservation corresponds to:

`AvailabilitySlot.status = RESERVED`

Only one ACTIVE Reservation may exist for a slot at a time.

```sql
CREATE UNIQUE INDEX idx_unique_active_reservation_per_slot
ON reservation(slot_id)
WHERE status = 'ACTIVE';
```

Historical `CONFIRMED`, `CANCELLED`, and `EXPIRED` Reservations remain stored and do not prevent later Reservations for the same slot.

# BOOKING (CORE)

```sql
CREATE TABLE booking (
    id BIGSERIAL PRIMARY KEY,
    reservation_id BIGINT NOT NULL UNIQUE REFERENCES reservation(id),
    client_id BIGINT NOT NULL REFERENCES "user"(id),
    specialist_id BIGINT NOT NULL REFERENCES specialist_profile(id),
    service_id BIGINT NOT NULL REFERENCES service(id),
    slot_id BIGINT NOT NULL REFERENCES availability_slot(id),

    status VARCHAR(20) NOT NULL CHECK (
        status IN ('CONFIRMED', 'CANCELLED')
    ),

    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    cancelled_at TIMESTAMP
);
```
Booking status represents only the confirmed/cancelled appointment lifecycle.

Temporary pre-confirmation state belongs to Reservation.

Post-session outcomes such as OCCURRED, DID_NOT_OCCUR, dispute, and unverified resolution are not encoded in `booking.status`.

Their persistence model is defined separately from the Booking status lifecycle.

`reservation_id` is unique because one Reservation may produce at most one Booking.

`slot_id` is intentionally not unique.

A slot may have multiple historical Bookings after cancellation and rebooking, while only one active Booking may occupy it at a time.

# КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ

## 1. Slot is atomic unit of availability

* one slot represents one concrete availability interval;
* a slot may have multiple historical Reservations and Bookings;
* only one current Reservation hold or Booking occupancy may exist at a time.

---

## 2. Reservation temporarily holds availability

* an ACTIVE Reservation temporarily holds an AvailabilitySlot;
* the slot transitions `FREE → RESERVED` when the hold is created;
* only one ACTIVE Reservation may exist for a slot at a time;
* Reservation confirmation transitions the slot `RESERVED → BOOKED` and produces a Booking;
* historical Reservations and Bookings remain stored;
* `booking.slot_id` is not unique because a cancelled Booking may be followed by rebooking of the same slot.

---

## 3. Soft lifecycle через status

- booking не удаляется
- все изменения через status transitions
