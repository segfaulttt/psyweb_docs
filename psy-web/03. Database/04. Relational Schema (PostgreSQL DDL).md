## Assumptions (важно зафиксировать)

- PostgreSQL
- `BIGSERIAL` как ID 
- Enums храним как `VARCHAR` + CHECK (чтобы не усложнять миграции)
- Booking — центральная транзакционная сущность
- Slot = atomic unit of availability

---

# USER


```
CREATE TABLE "user" (
    id BIGSERIAL PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,    
    password_hash VARCHAR(255) NOT NULL,    
    role VARCHAR(20) NOT NULL CHECK (role IN ('CLIENT', 'SPECIALIST', 'ADMIN')),
    status VARCHAR(20) NOT NULL CHECK (status IN ('ACTIVE', 'BLOCKED', 'PENDING')),
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

---

# SPECIALIST_PROFILE

```
CREATE TABLE specialist_profile (    
	id BIGSERIAL PRIMARY KEY,    
	user_id BIGINT NOT NULL UNIQUE REFERENCES "user"(id) ON DELETE CASCADE,
	first_name VARCHAR(100),    
	last_name VARCHAR(100),    
	bio TEXT,    
	verified BOOLEAN DEFAULT FALSE,    
	rating_avg DOUBLE PRECISION DEFAULT 0
);
```

---

# CLIENT_PROFILE

```
CREATE TABLE client_profile (
    id BIGSERIAL PRIMARY KEY,    
    user_id BIGINT NOT NULL UNIQUE REFERENCES "user"(id) ON DELETE CASCADE,    
    first_name VARCHAR(100),    
    last_name VARCHAR(100)
);
```

---

# SERVICE

```
CREATE TABLE service (    
	id BIGSERIAL PRIMARY KEY,    
	specialist_id BIGINT NOT NULL REFERENCES specialist_profile(id) ON DELETE CASCADE,
	title VARCHAR(255) NOT NULL,    
	description TEXT,    
	duration_minutes INT NOT NULL CHECK (duration_minutes > 0),    
	price NUMERIC(10,2),    
	is_active BOOLEAN DEFAULT TRUE
);
```

---

# AVAILABILITY_SLOT

```
CREATE TABLE availability_slot (
    id BIGSERIAL PRIMARY KEY,    
    specialist_id BIGINT NOT NULL REFERENCES specialist_profile(id) ON DELETE CASCADE,    
    start_time TIMESTAMP NOT NULL,    
    end_time TIMESTAMP NOT NULL,    
    status VARCHAR(20) NOT NULL CHECK (status IN ('FREE', 'BOOKED', 'BLOCKED'))
);
```

### Critical constraint (no double booking per slot)

```
CREATE UNIQUE INDEX idx_unique_slot_booking
ON availability_slot (id)
WHERE status = 'BOOKED';
```

(логика дублируется сервисом — но это страховка)

# BOOKING (CORE)

```
CREATE TABLE booking (
    id BIGSERIAL PRIMARY KEY,    
    client_id BIGINT NOT NULL REFERENCES "user"(id),    
    specialist_id BIGINT NOT NULL REFERENCES specialist_profile(id),
    service_id BIGINT NOT NULL REFERENCES service(id),
    slot_id BIGINT NOT NULL UNIQUE REFERENCES availability_slot(id),
    
    status VARCHAR(20) NOT NULL CHECK (        
	    status IN ('CREATED', 'CONFIRMED', 'CANCELLED', 'COMPLETED', 'NO_SHOW')
	),
	created_at TIMESTAMP NOT NULL DEFAULT NOW(),
	cancelled_at TIMESTAMP
);
```

# REVIEW

```
CREATE TABLE review (
    id BIGSERIAL PRIMARY KEY,    
    booking_id BIGINT NOT NULL UNIQUE REFERENCES booking(id) ON DELETE CASCADE,
    client_id BIGINT NOT NULL REFERENCES "user"(id),
    specialist_id BIGINT NOT NULL REFERENCES specialist_profile(id),
    rating INT NOT NULL CHECK (rating BETWEEN 1 AND 5),
    comment TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

# CHAT_THREAD

```
CREATE TABLE chat_thread (
	id BIGSERIAL PRIMARY KEY,
	booking_id BIGINT NOT NULL UNIQUE REFERENCES booking(id) ON DELETE CASCADE,
	client_id BIGINT NOT NULL,
	specialist_id BIGINT NOT NULL
);
```

---

# MESSAGE

```
CREATE TABLE message (
    id BIGSERIAL PRIMARY KEY,
    thread_id BIGINT NOT NULL REFERENCES chat_thread(id) ON DELETE CASCADE,
    sender_id BIGINT NOT NULL,
    text TEXT NOT NULL,
    sent_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

# КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ

## 1. Slot is atomic unit

- один slot = одна возможная бронь

---

## 2. Booking owns slot reservation

- booking.slot_id UNIQUE гарантирует отсутствие дублей

---

## 3. Soft lifecycle через status

- booking не удаляется
- все изменения через status transitions
