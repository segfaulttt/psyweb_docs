
# 06. Функциональные направления продукта (Product Backlog Overview)

**Проект:** PsyWeb  
**Статус:** DRAFT  
**Область:** Функциональная структура продукта

---

# 1. Назначение документа

Документ содержит обзор основных функциональных направлений PsyWeb.

Он помогает видеть продукт целиком и понимать, какие возможности относятся к основному ядру, а какие предусмотрены для последующего развития.

Документ не используется для управления отдельными задачами разработки.

Для этого применяется Jira, где фиксируются:

- задачи;
- приоритеты;
- статусы;
- зависимости;
- исполнители;
- результаты реализации.

Настоящий документ не должен дублировать оперативное состояние Jira.

---

# 2. Основные функциональные направления

## 2.1. User Management

Содержит:

- регистрацию пользователей;
- аутентификацию;
- авторизацию;
- управление состоянием аккаунта;
- базовые данные пользователя.

## 2.2. Client Profile

Содержит:

- просмотр собственного профиля;
- изменение разрешённых данных;
- просмотр истории консультаций;
- просмотр предстоящих консультаций.

Расширения:

- фотографии профиля;
- дополнительные персональные настройки.

## 2.3. Specialist Management

Содержит:

- регистрацию специалиста;
- модерацию;
- профессиональный статус;
- административное ограничение BookingAccess;
- базовый профиль специалиста.

Расширения:

- образование;
- сертификаты;
- специализации;
- профессиональный опыт;
- расширенная публичная страница.

## 2.4. ServiceOffering

Содержит:

- создание услуг;
- редактирование услуг;
- деактивацию услуг;
- длительность консультации;
- перерыв после консультации;
- условия и характеристики услуги.

## 2.5. Schedule

Содержит:

- REGULAR;
- FLOATING;
- недельные версии расписания;
- исключения для отдельных дат;
- управление рабочими интервалами;
- горизонт бронирования;
- часовой пояс.

## 2.6. Availability

Содержит:

- динамический расчёт доступных начал;
- учёт длительности выбранной услуги;
- учёт перерывов;
- учёт ScheduleOccupancy;
- временные ограничения;
- проверку допуска специалиста.

Сохраняемые AvailabilitySlot не используются.

## 2.7. Reservation

Содержит:

- создание временного удержания;
- системный TTL;
- подтверждение Reservation;
- отмену;
- истечение;
- сохранение истории.

## 2.8. Booking

Содержит:

- создание подтверждённой консультации;
- просмотр предстоящих консультаций;
- историю записей;
- отмену;
- фиксацию метаданных отмены;
- освобождение Occupancy.

## 2.9. SessionOutcome

Содержит:

- отчёты клиента и специалиста;
- причины несостоявшейся консультации;
- reporting window;
- автоматическое разрешение совместимых результатов;
- обработку отсутствующих ответов;
- административное разрешение споров.

## 2.10. Review

Содержит:

- eligibility после RESOLVED / OCCURRED;
- создание Review;
- ограничение один Review на пару;
- редактирование;
- расчёт рейтинга специалиста.

## 2.11. Administration

Содержит:

- рассмотрение заявок специалистов;
- профессиональное одобрение;
- приостановку допуска;
- управление BookingAccess;
- разрешение спорных Outcome;
- предусмотренный административный аудит.

## 2.12. Notification

Содержит:

- внутриплатформенные уведомления;
- просмотр уведомлений;
- статус прочтения;
- реакцию на значимые бизнес-события.

# 3. Поиск и каталог специалистов

Платформа предусматривает:

- каталог специалистов;
- поиск;
- просмотр публичных профилей;
- просмотр услуг.

Дополнительные возможности:

- фильтры;
- сортировки;
- расширенные критерии подбора.

Точный минимальный набор поиска определяется продуктовыми требованиями.

---

# 4. Дополнительные функциональные направления

## 4.1. Communication

Необязательный чат между клиентом и специалистом.

Требует отдельного согласования правил доступа и доставки сообщений.

## 4.2. Video Consultations

Встроенная видеосвязь.

Не является частью MVP.

## 4.3. Payments

Обработка платежей внутри платформы.

Не является частью MVP.

## 4.4. Analytics

Расширенные отчёты, статистика и административные панели.

## 4.5. Email Verification

Подтверждение адреса электронной почты.

## 4.6. Password Recovery

Безопасное восстановление учётных данных.

## 4.7. Calendar Integration

Синхронизация консультаций с внешними календарями.

## 4.8. Mobile Application

Отдельное мобильное клиентское приложение.

## 4.9. AI-assisted Features

Дополнительные интеллектуальные функции.

Требуют отдельного продуктового и технического проектирования.

# 5. Границы MVP

## Основное ядро

Целевая первая версия ориентирована на:

- User и Authentication;
- Authorization;
- Specialist и модерацию;
- ServiceOffering;
- Schedule;
- Availability;
- Reservation;
- Booking;
- SessionOutcome;
- Review;
- необходимый Admin;
- базовый Notification.

## Отдельно планируемые расширения

- Chat;
- Video;
- Payments;
- расширенная Analytics;
- мобильное приложение;
- календарные интеграции;
- AI-assisted функции.

## Уточнение

Некоторые функциональные направления могут разрабатываться поэтапно.

Включение направления в основное ядро не означает, что каждая его дополнительная возможность обязательна для первой версии.

# 6. Управление реализацией

Единственным оперативным источником состояния задач разработки является Jira.

Документ не содержит собственных статусов Planned, In Progress, Done или Blocked.

Для конкретной функциональности в Jira могут существовать:

- несколько независимых задач;
- технические задачи;
- тестовые задачи;
- документационные задачи;
- зависимости между задачами.

Поэтому функциональные направления не должны искусственно сопоставляться с одной задачей или одним статусом.
