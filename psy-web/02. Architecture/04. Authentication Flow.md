
**System:** PsyWeb Backend  
**Auth Type:** JWT (Stateless Authentication)

---

# Overview

This document describes how authentication works in the system using JWT-based security.

The system is **stateless**, meaning no session is stored on the server.

---

# Key Components

- Authentication Controller
- User Service
- Password Encoder (BCrypt)
- JWT Service
- Security Filter Chain
- SecurityContext

---

# 1. Login Flow

## Step 1: User submits credentials

User sends request:

```text
POST /auth/login
```

Payload:
- email
- password

---

## Step 2: Authentication request reaches controller

Controller delegates to authentication service.

---

## Step 3: User validation

System:
- finds user by email
- verifies password using BCrypt
- checks account status (Active only)

If invalid:
→ authentication fails

---

## Step 4: JWT generation

If credentials are valid:

System generates JWT containing:
- userId
- role (CLIENT / SPECIALIST / ADMIN)
- status
- expiration time

---

## Step 5: Token returned to client

Response:

```json
{
  "token": "jwt.token.here"
}
```

---

# 2. Authenticated Request Flow

## Step 6: Client sends request with token

```text
Authorization: Bearer <JWT>
```

---

## Step 7: JWT Filter intercepts request

Spring Security filter:

- extracts token
- validates signature
- checks expiration
- parses claims

If invalid:
→ request rejected (401)

---

## Step 8: SecurityContext setup

If valid:

System creates:

```text
Authentication object
```

Stored in:

```text
SecurityContextHolder
```

This makes user identity available globally in request scope.

---

# 3. Authorization Check

## Step 9: Access decision

After authentication:

System checks:

- user role
- endpoint permissions
- method-level security (@PreAuthorize)

Example:

```java
@PreAuthorize("hasRole('SPECIALIST')")
```

If access denied:
→ 403 Forbidden

---

# 4. Password Security

## Password Storage

- passwords are never stored in plain text
- BCrypt hashing is used

---

## Password Verification

```text
rawPassword → BCrypt.compare → hashedPassword
```

---

# 5. Token Structure

JWT contains:

- subject (user id)
- role
- status
- expiration time

Signed using secret key.

---

# 6. Token Expiration

When token expires:

- user must re-authenticate
- system rejects request with 401

---

# 7. Logout Flow (Stateless)

Since system is stateless:

- logout is handled client-side
- token is deleted from storage

Optional future improvement:
- token blacklist (Redis)

---

# 8. Security Rules

## SR-001
Only Active users can authenticate successfully.

## SR-002
Rejected or Suspended users cannot obtain valid JWT.

## SR-003
JWT must be validated on every request.

## SR-004
Authorization is always checked after authentication.

---

# 9. Example Full Flow (Login → Request)

```text
1. POST /auth/login
2. Validate credentials
3. Generate JWT
4. Client stores token

5. GET /appointments
6. Send JWT in header
7. Filter validates token
8. SecurityContext set
9. Controller executes request
```

---

# Notes

## Stateless Design

The system does not store sessions:
- scalability friendly
- works with load balancers
- no server memory dependency

---

## Security Layer Position

Authentication happens:
→ BEFORE controller
→ INSIDE Spring Security filter chain

Authorization happens:
→ AFTER authentication
→ at controller/service level
