
**System Type:** Modular Monolith (Spring Boot)

---

# Overview

The system is divided into **domain-based modules**, each representing a bounded context.

Each module contains:
- Controller layer (API)
- Service layer (business logic)
- Repository layer (data access)
- Domain model (entities + domain rules)

Modules communicate via **service interfaces**, not direct repository access.

---

# Dependency Rules

## Allowed Rule:

- Modules can depend on `common`
- Domain modules may depend on each other only via service interfaces

---

## Forbidden Rule:

- No direct repository access between modules
- No circular dependencies
- No cross-domain entity modification without service layer

---

# Communication Style

Modules communicate via:

- Service calls (synchronous)
- Domain events (future extension)

---

# Future Evolution

This structure allows:

- extraction of Booking into microservice
- Chat into real-time service
- Notification into async worker service

without changing domain logic.

---

# Notes

This module structure is designed to:

- enforce separation of concerns
- reduce coupling
- support scalability
- reflect real-world backend architecture patterns
